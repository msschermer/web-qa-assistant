Web QA Assistant 1.6.0
Release focus: reliable Chrome on-device Frank readiness, isolated per-finding reasoning sessions, evidence-vs-reasoning focus mode, stronger recommendation quality, and adversarial production hardening over the complete 1.5.2 feature set.
Automated validation: 168/168 tests PASS; npm run check PASS across 55 JavaScript files; npm run build:extension PASS without node_modules by preserving the packaged axe runtime; RELEASE_TAG=v1.6.0 npm run release:validate PASS.
Frank lifecycle: Browser QA is independent from model readiness. First-use preparation/download progress is surfaced in place, pending findings remain available, and Rescan contains no AI-recovery behavior. One system-only base Prompt API session may stay warm; each finding uses and destroys an isolated clone.
UI contract: the sidebar is the deterministic evidence ledger and the centered focus card is Frank's interpretation/action surface beside the spotlighted real element. Walkthroughs begin with interpretation rather than a low-value standalone locate step.
Cost boundary: routine extension scans call no model provider. Chrome built-in AI is preferred for Ask Frank. Extension cloud AI and public web AI both default off and require explicit server enablement before metered provider usage is possible.
Security boundary: provider keys and managed-install signing secrets remain server-side. No shared assistant token is bundled. Page-derived strings are untrusted prompt data and can never authorize destructive or secret-handling actions. Cross-site task isolation is regression-tested.
AI reliability: local AI may improve only summary/interpretation/impact/remediation/verification text. Deterministic findings, targets, evidence refs, metrics, assessment and verification actions remain authoritative. Generic output, semantic drift, unsupported page positions/components/business claims, invented values/standards/URLs/contrast ratios, decorative-alt regressions, performance overclaims, and high-risk prompt-injection output are rejected.
Numerical reliability: evidence-derived contrast-color suggestions are rechecked after RGB rounding; seeded adversarial cases verify the emitted color actually meets the stated threshold.
Build integrity: release-source extension rebuilds retain the vendored axe-core runtime and icons even when node_modules is absent, avoiding the prior failed-build asset deletion mode.
Fixture policy: release tests and acceptance fixtures use neutral synthetic labels and reserved example domains only; real external test-site identities and copied site content are prohibited.
Runtime acceptance note: automated Chromium in this environment could not provide a usable extension/on-device Prompt API acceptance surface. The user's previous real desktop Chrome proved 1.5.2 on-device reasoning; final 1.6.0 readiness-transition/focus-mode acceptance still requires one qualifying real-desktop-Chrome run after installing this release candidate.
